# rewrite-from-skill-bot

Telegram-бот, переписывающий сообщения в стиле из `runtime_skills/rewrite/SKILL.md`
и подключённых справочников. Стиль лежит в файлах и подхватывается на лету —
перезапуск не нужен.

## Поведение

В личных чатах режим задаётся `PRIVATE_ACCESS`: `open` разрешает обработку любому пользователю, `allowlist` требует ID пользователя в `ALLOWED_CHAT_IDS`. В группах и супергруппах всегда нужны реальное упоминание бота и ID чата в allowlist; каналы игнорируются. В личном чате упоминание не нужно: отправьте текст или ответьте на сообщение. Команды `/start` и `/help` показывают справку.

Личные чаты ограничены `PRIVATE_USER_LIMIT_PER_HOUR` (10) на пользователя и `PRIVATE_GLOBAL_LIMIT_PER_DAY` (500) суммарно. `MAX_SOURCE_CHARS` ограничивает исходник (3000). В режиме `open` лимиты снижают риск расходов, но не исключают его: текст отправляется стороннему LLM-провайдеру. Содержимое сообщений в логи не записывается.

В группах бот отвечает **только** если в сообщении есть упоминание `@username` бота. В открытом личном чате упоминание не требуется.

| Сообщение | Что переписывается | Пожелание |
|---|---|---|
| `@bot текст` | текст после упоминания | — |
| reply + `@bot` | текст или подпись reply-сообщения | — |
| reply + `@bot сделай короче` | текст или подпись reply-сообщения | `сделай короче` |
| reply + `@bot` (reply без текста) | — | ошибка: только текст или подпись к медиа |
| reply + `@bot` (в reply только `@bot`) | — | ошибка: в цитате есть только упоминание |
| `@bot` без текста и без reply | — | подсказка |
| reply без упоминания | бот молчит | — |
| личное сообщение в режиме `open` | текст/подпись сообщения | — |
| личный reply | текст/подпись процитированного сообщения | текст reply — пожелание |
| личный forward | текст/подпись пересланного сообщения | — |
| обычное сообщение в группе без упоминания | бот молчит | — |
| `@другойбот текст` | бот молчит | — |

При reply исходным текстом **всегда** является процитированное сообщение.
Текст рядом с упоминанием — только дополнительное пожелание и никогда не заменяет reply.
Упоминание внутри процитированного сообщения тоже вырезается из исходного текста.

Упоминание ищется по `MessageEntity`, а не подстрокой, регистр не важен.
Поддержаны `mention` и `text_mention`, а также `caption`/`caption_entities`.
Смещения считаются в UTF-16 code units, поэтому эмодзи перед упоминанием не ломают разбор.

## Как работает

1. `MentionFilter` пропускает сообщение только при реальном упоминании бота.
2. `AllowedChatFilter` отсекает чаты вне `ALLOWED_CHAT_IDS`.
3. `core/message_resolver.py` строит `source_text` и `user_instruction`.
4. Дедупликация по `(chat_id, message_id)`, затем rate limit.
5. `core/style_loader.py` собирает стиль из SKILL.md и подключённых справочников.
6. `llm/client.py` подставляет стиль в system prompt и вызывает LLM.

Парсинг идёт **до** rate limit, поэтому пустые и некорректные запросы не расходуют квоту.

## Запуск

```bash
cp .env.example .env   # заполнить BOT_TOKEN, LLM_API_KEY, ALLOWED_CHAT_IDS
pip install -e ".[dev]"
python src/main.py
```

`ALLOWED_CHAT_IDS` пустой по умолчанию: в группах это означает fail-closed; личные чаты
в режиме `open` работают независимо от списка. `PRIVATE_ACCESS=allowlist` требует ID
пользователя в списке; `open` включает личные сообщения для всех.

## Модель

По умолчанию — OpenRouter `poolside/laguna-s-2.1` (free):

```env
LLM_API_URL=https://openrouter.ai/api/v1/chat/completions
LLM_API_KEY=sk-or-...
LLM_MODEL=poolside/laguna-s-2.1
```

Любой OpenAI-совместимый endpoint работает через те же три переменные.

`response_format` не входит в список поддерживаемых полей этой модели и может дать 400,
поэтому `LLM_JSON_MODE=false` по умолчанию: клиент берёт `{"text": ...}`, если модель
вернула JSON, иначе использует текст как есть.

## Повторы и ошибки

| Код | Поведение |
|---|---|
| 429 | повтор с backoff, уважая заголовок `Retry-After` (потолок 30 с) |
| 5xx, timeout, connect error | повтор с backoff |
| 400, 401, 402, 403, 404 | без повторов, своё сообщение пользователю |

Всего 3 попытки. Паузы между попытками — экспоненциальный backoff с jitter:
`min(1.0 * 2^(n-1), 8 с)` плюс случайные 0–25 %. То есть примерно 1 с → 2 с → 4 с.
Константы `RETRY_BASE_SECONDS`, `RETRY_MAX_SECONDS`, `MAX_RETRY_AFTER_SECONDS`
заданы в `src/llm/client.py`.

Ответ 200 с некорректным телом (не-JSON, `choices` не список, `message` не объект)
повтором не считается — это ошибка модели, а не сбой транспорта.

Пустой ответ модели показывается как «пустой ответ», а не как внутренняя ошибка.
Тексты сообщений и ключи в логи не пишутся.

## Лимиты и защита от спама

Срабатывание лимита пользователя или чата отвечает один раз на ключ
(`(chat_id, user_id)` и `chat_id` соответственно). Пока не истечёт время,
указанное в ответе, бот молчит вместо повторных предупреждений.

Заглушка и rate limit живут в памяти процесса (`ponytail:` в
`core/rate_limiter.py`) — при нескольких инстансах нужен общий стор.

## Стиль и справочники

Структура:

```
runtime_skills/rewrite/
├── SKILL.md              основной стиль
└── references/
    └── genres.md         справочник по жанрам
```

Подключаются **только те файлы, на которые есть ссылка в SKILL.md** вида
`references/<имя>.md` — в frontmatter, в обычном тексте, в `` `коде` `` или в
markdown-ссылке. Файл, лежащий в `references/`, но не упомянутый в SKILL.md,
в prompt не попадает.

Ссылка стоит в YAML-frontmatter, поэтому в prompt не попадает: модель видит
только раздел «Справочник: …» ниже. Порядок подключения — по первому появлению
ссылки, повторы игнорируются. Если ссылок нет, поведение прежнее: в prompt уходит
только SKILL.md.

Собранная строка стиля выглядит так:

```
<текст SKILL.md без frontmatter>

---
## Справочник: genres.md
<содержимое genres.md без frontmatter>
```

Разделитель и заголовок фиксированы, порядок детерминирован. Заголовок берётся из
имени файла, а не из его содержимого.

Ограничения (`src/core/style_loader.py`):

| Константа | Значение |
|---|---|
| `MAX_REFERENCE_BYTES` | 32 КБ на файл |
| `MAX_REFERENCES_TOTAL_BYTES` | 64 КБ суммарно |

Правила безопасности: путь обязан находиться внутри `references/`
(симлинки наружу, `..`, абсолютные пути и вложенные папки отклоняются),
только `.md`, только UTF-8.

При ошибках: пустой или нечитаемый справочник пропускается, остальные грузятся.
Если SKILL.md или справочник сломались после успешной загрузки, бот продолжает
использовать последнюю удачную версию. Кэш пересобирается целиком и только
после успешного чтения SKILL.md, поэтому частичное состояние в кэш не попадает.
Кэш инвалидируется по mtime SKILL.md и любого подключённого справочника —
рестарт не нужен. В логи пишутся только имя файла, класс исключения и размер,
содержимое файлов не логируется.
